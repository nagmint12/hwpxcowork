# Cowork 드라이브 연결

2026-10-29. cowork 서버에 접속해서 함께 편집하는 기존 방식은 유지한다. 오른쪽 기본 탭은 AI 작업 / 메모 / 드라이브이며, 자세히 보기에서 변경 요청·변경 추적·첨부·이력을 연다. 문서 목록 상단에서도 드라이브를 열 수 있다.

## 확인 결과

현재 확장 버전은 **0.6.0**이다. 사용자별 개인 프로젝트를 동적으로 확인한다. 연결 후 별도 실행 창을 켜 둘 필요가 없다. 브라우저는 실행 중이어야 하며 로그인은 사용자가 직접 진행한다.

일반 cowork 웹페이지에서 로그인된 두레이의 다른 출처 탭을 읽을 수는 없다. 실제 `http://localhost:8787` 페이지에서 두레이 드라이브 정보에 credentials 포함 요청을 보내면 브라우저에서 `TypeError: Failed to fetch`로 차단되는 것을 확인했다. iframe·서버 프록시만으로 사용자의 로그인 상태를 공유할 수도 없다.

따라서 Chrome Manifest V3 확장프로그램을 사용한다. 두레이 로그인은 사용자가 직접 진행한다. SSO 확장과 연동하거나 아이디·비밀번호·쿠키를 cowork 서버에 전송하지 않는다. 두레이 페이지의 격리된 실행 환경에서 웹사이트가 사용하는 요청으로 작업하고, 선택한 파일 바이트와 정리한 목록만 서버와 교환한다. 이 요청들은 공식 공개 API 계약이 아니므로 두레이가 변경하면 어댑터 수정이 필요하다.

## 설치·연결

### 0.6.0: 사용자별 개인 프로젝트 (2026-11-02)

고정 프로젝트 ID를 제거했다. 같은 브라우저에서 두레이에 로그인하고 개인 프로젝트를 연다. cowork 드라이브를 열거나 새로고침하면 확장이 `/drive/{projectId}` 주소에서 후보 ID를 읽고, 로그인된 탭에서 `/v2/wapi/drives/{projectId}` 응답의 `projectId`, `type: private`, `id`(실제 드라이브 ID)를 검사한다. 공유 프로젝트는 제외하고 서로 다른 개인 프로젝트가 둘 이상이면 자동 선택하지 않는다. 기본 `/drive/` 주소가 개인 프로젝트로 이동하는 환경은 자동으로 확인할 수 있다.

서버는 확장 전용 인증으로 확인 결과를 받은 뒤 개인 프로젝트 ID만 해당 cowork 사용자의 `bridge.projectId`에 저장한다. 폴더·파일 목록은 저장하지 않는다. 파일 작업은 등록된 ID와 같은 대상만 허용하며, 확장도 작업마다 현재 주소와 개인 드라이브 여부를 재검사한다. 실제 파일 API의 드라이브 ID는 응답에서 사용하며 서버에는 저장하지 않는다. 연결 해제·재연결 시 프로젝트 범위를 초기화한다. 브라우저 계정 변경 후에는 두레이 개인 프로젝트를 열고 cowork 드라이브를 새로고침한다. 기존 확장은 0.6.0 이상으로 업데이트해야 한다.

### 0.5.0: 버튼 하나로 연결·다시 켜도 유지 (2026-10-30)

코드 복사와 서버 주소 입력을 없앴다. 로그인한 cowork 화면을 연 탭에서 확장 아이콘을 누르고 **이 cowork 서버에 연결**을 누르면 연결된다. 처음 한 번 그 서버의 사이트 접근을 허용한다. 내부에서는 다음 순서로 진행한다. 아이콘을 누른 동안만 받은 탭 접근(`activeTab`)으로 그 탭 안에서 cowork 토큰을 써 5분짜리 한 번 쓰는 연결 코드를 받는다. 이어서 그 코드를 확장 전용 토큰으로 바꾼다. cowork 토큰은 탭 밖으로 나오지 않는다. 확장 토큰은 해시만 `dataDir/drive/<사용자 해시>/index.json` 의 `bridge` 에 저장한다. 그래서 **서버를 다시 켜도 다시 연결할 필요가 없다.** 연결 해제하면 지우고, 설정에서 지운 사용자의 연결은 되살리지 않으며 역할은 지금 설정을 따른다. 다른 브라우저의 확장을 연결할 때만 아래의 코드 입력 방식(**코드로 연결**)을 쓴다.

확장은 두레이 드라이브 기능에만 필요하다. 문서 편집·공동 검토·AI 요청·MCP 는 확장 없이 동작한다.

아래는 0.4.0 까지의 코드 입력 방식이다(지금은 다른 브라우저용 선택지).

1. `npm run package:drive`로 `artifacts/cowork-drive-bridge.zip`을 만든다. 또는 cowork 왼쪽 **드라이브 → 연결 설정 → 확장프로그램 받기**를 누른다.
2. ZIP을 폴더에 풀고 Chrome `chrome://extensions` 또는 Brave `brave://extensions`에서 개발자 모드를 켠다. **압축해제된 확장 프로그램을 로드합니다**로 그 폴더를 선택한다.
3. cowork에 로그인하고 **드라이브 → 연결 설정 → 연결 코드 발급**을 누른다.
4. 확장 아이콘에서 cowork 서버의 기본 주소와 코드를 입력한다. 코드는 5분간 한 번만 사용할 수 있다. HTTPS 또는 localhost·루프백·사내망 IPv4(10.x, 172.16~31.x, 192.168.x) HTTP를 허용한다. 사이트 접근 권한은 사용자가 입력한 서버 하나에 대해서만 요청한다.
5. **별도 실행 창은 필요 없다.** 연결 후 확장 서비스 워커가 백그라운드에서 처리한다. 브라우저는 실행 중이어야 한다. 서버 재시작 후에는 새 코드로 다시 연결한다. 연결 상태 화면은 필요할 때만 열고 닫아도 된다. 코드 등록만으로 연결됨이라고 표시하지 않고 실제 백그라운드 통신을 확인한다.
6. 같은 브라우저에서 두레이에 직접 로그인한다. 로그인 만료 시 **연결 설정 → 연결된 브라우저에서 두레이 열기**로 다시 로그인한다.

확장 설치와 사이트 권한 허용은 사용자가 브라우저에서 진행해야 한다. 개발 중에는 확장 설치 자체를 자동으로 승인하거나 사용자 브라우저 설정을 바꾸지 않았다.

### Chrome·Brave 수정판 0.3.1

기존 설치 폴더에 새 ZIP의 파일을 덮어쓴 뒤 `brave://extensions`에서 **Cowork 드라이브 연결의 새로고침**을 누른다. 기존 실행 창을 닫고 확장 아이콘에서 새 코드로 연결한다. 새 실행 창은 자동으로 열지 않는다. 로그인은 반드시 확장을 설치한 같은 Brave에서 직접 한다. Ego Lite·Chrome의 로그인은 Brave로 공유되지 않는다. cowork의 **연결된 브라우저에서 두레이 열기**를 누르면 실제 연결된 Brave에 개인 프로젝트 탭이 열린다.

0.3.1 배포에는 두레이 어댑터와 연결 화면만 포함한다. 별도 계정 OAuth 권한을 요청하지 않으며 브라우저 잠금 API가 없는 경우도 지원한다. 두레이 주입 함수의 오류는 결과에 담아 반환해 로그인 만료·사이트 접근 권한·원격 파일 변경 등을 cowork 화면에서 확인할 수 있게 했다.

### ngrok와 백그라운드 동작

0.2.0에서는 ngrok 경유 요청이 안내 페이지 `ERR_NGROK_6024`를 받아 `Unexpected token '<'` 오류로 보일 수 있었다. 사용자가 제공한 실제 ngrok 주소에서 브라우저 요청을 재현했고, `ngrok-skip-browser-warning: 1`을 넣으면 안내 HTML 대신 API JSON이 반환되는 것을 확인했다. 0.3.0은 연결 코드 등록·작업 조회·결과·파일 업로드/다운로드에 이 헤더를 공통 적용한다. JSON 형식과 HTML 응답도 검사해 터널 오류를 명확히 표시한다. [ngrok 공식 안내](https://ngrok.com/docs/pricing-limits/free-plan-limits#using-headers).

작업 도착은 전용 WebSocket으로 알리고 파일 바이트는 기존 인증된 HTTP 경로로 전송한다. 브리지 토큰은 URL에 넣지 않는다. Chrome 120 이상에서 브라우저 알람을 복구 수단으로 사용하며, 지원되는 WebSocket 통신으로 유휴 상태에서도 도착 알림을 받는다. WebSocket이 끊기면 최대 약 30초 간격으로 연결을 복구한다. 원격 쓰기는 서버에서 한 번만 선점하고 자동 반복하지 않는다.

두레이 탭이 없을 때는 작업용 비활성 탭을 만들고 작업이 끝나면 닫는다. 사용자가 이미 연 탭은 유지하며, 작업용 탭을 사용자가 직접 활성화한 경우도 닫지 않는다. 처음 로그인하거나 로그인 세션이 만료됐을 때는 사용자 로그인 화면이 필요하다. 브라우저나 PC가 종료된 동안에는 확장이 동작하지 않는다.

## 사용 흐름

문서 목록 왼쪽에는 **공용 문서함 → 개인 문서함 → 드라이브**가 표시된다. 드라이브를 선택해도 이 메뉴를 유지하며 문서함이나 폴더를 선택하면 문서 목록으로 돌아간다. 드라이브 화면은 프로젝트·폴더 나무, 상단 작업 버튼·경로·검색, 중앙 파일 목록으로 구성한다. 우측 상단 **크게 보기**로 탐색기를 펼치고 Esc로 닫을 수 있다. 편집기 안에는 드라이브 메뉴를 표시하지 않는다. 편집기용 패널 정의는 `web/drive-editor.js`에 사용 중지 상태로 보관하고 공통 탐색기는 `web/drive-explorer.js`로 유지한다.

- **자동 목록 연결**: 브라우저가 연결되면 개인 프로젝트를 확인하고 폴더를 읽는다. 폴더 이름을 클릭하면 이동하고 경로 또는 상위 폴더 버튼으로 돌아간다. 왼쪽 나무에는 사용자가 열어 본 경로와 그 목록에 나온 폴더만 표시한다. 한 폴더의 한 쪽(최대 50개)만 읽고 하위 폴더를 재귀적으로 탐색하지 않는다. 서버는 사용자별로 확인된 개인 프로젝트만 허용한다.
- **파일 선택·열기·찾기**: 이름을 클릭해 파일을 선택하거나 체크박스로 여러 파일을 선택한다. Ctrl/Cmd+클릭으로 선택을 추가한다. 외부 HWPX를 더블클릭하거나 Enter로 열면 저장할 문서함·폴더를 선택한 뒤 **가져와서 열기**로 편집기에 진입한다. 문서함에 이미 저장한 문서는 더블클릭·Enter·문서 열기 버튼으로 바로 연다. 편집기에서 목록으로 돌아오면 마지막 문서함/드라이브 화면을 복원한다(탭별·사용자별 세션 저장). 검색은 현재 불러온 목록에만 적용되며 이름 정렬을 지원한다. 이전·다음 버튼으로 페이지를 바꾼다.
- **업로드**: PC 파일을 선택하거나 목록에 끌어 놓으면 현재 폴더에 바로 올린다. 여러 파일을 순서대로 처리하고 완료 후 목록을 갱신한다. 같은 이름이 있어도 자동 덮어쓰기를 하지 않는다.
- **다운로드**: 선택한 파일을 PC에 저장한다. 서버가 파일을 중계하지만 별도의 전송 준비 단계는 없다.
- **편집함으로 가져오기**: HWPX를 선택한 뒤 내 개인편집함 또는 공용편집함과 저장할 폴더를 고른다. 작성 가능한 위치만 제시하고 서버에서도 권한을 다시 검사한다. 새 문서는 대상 폴더의 공유 권한을 따르며 두레이 원본은 유지된다. 가져온 뒤 문서 목록을 갱신하고 **문서 열기** 링크를 제공한다. 마지막으로 선택한 편집함 위치를 기본 목적지로 제시한다. 현재 편집기로 가져올 수 있는 형식은 HWPX이며, HWP는 한글에서 HWPX로 변환해야 한다. 다른 형식도 업로드·다운로드는 가능하다.
- **추가 작업(···) → 편집함 문서 올리기**: 읽을 수 있는 공용·개인 문서를 골라 현재 드라이브 폴더에 바로 올린다. 현재 편집 중인 문서는 저장을 먼저 확인한다. 저장된 공동 문서를 사용하며 승인 대기 중인 개인 수정본은 포함하지 않는다.
- **추가 작업 → 선택 파일 교체**: 현재 목록에서 원본 하나를 고르고 새 PC 파일을 선택한 뒤 위치·파일 이름을 확인한다. 업로드 직전 revision을 다시 읽어 변경이 있으면 중단한다. 두레이의 검사와 쓰기는 별도 요청이므로 그 사이 변경까지 원자적으로 막는 것은 보장하지 않는다.
- **AI 결과·서버 보관 파일**: 편집함 문서 올리기 창의 접힌 목록에서 기존 AI 결과 파일을 올리거나 현재 문서의 AI 첨부로 추가할 수 있다. 보관 사본 지우기는 해당 사본만 지우며 편집함 문서와 원격 파일에는 영향을 주지 않는다.

직접 업로드·다운로드·가져오기에서 사용하는 임시 전송 사본은 성공 후 정리한다. 전송 결과가 불명확하거나 실패하면 사본을 남겨 재확인할 수 있게 한다. 기존 AI 결과·보관 파일은 자동 정리하지 않는다. 같은 페이지 안에서 다른 탭이나 편집함으로 이동해도 시작한 전송은 계속 처리하고 완료·실패를 알린다. 브라우저 페이지를 닫거나 새로고침하면 이 보장은 적용되지 않으므로 원격 결과를 확인한다.

파일 한도는 50MiB와 서버 첨부 제한 중 작은 값이다. 보관함은 사용자별 50개·파일 한도의 5배까지다. 전송 파일은 `dataDir/drive/<사용자 이름 해시>/`에 저장되고 다른 사용자의 드라이브 API에서는 읽을 수 없다. 문서에 첨부하거나 공동 편집 문서를 만들면 기존 공동 문서의 공유 규칙이 적용된다.

## 별도 보관한 연동

현재 제공하는 드라이브는 두레이 개인 프로젝트뿐이다. 미완성인 Google Drive 코드는 [별도 보관 폴더](../integrations/google-drive/README.md)로 분리했다. 웹 메뉴·확장 설정·OAuth 권한·배포 ZIP·서버 공급자·AI 탐색 문맥에서 제외한다. 이전에 저장한 비활성 공급자의 탐색 문맥·제안은 노출하거나 실행하지 않는다. 기존에 내려받은 개인 보관 파일과 편집함 문서는 유지한다.

## 개인정보 정책 (2026-10-30, 확장 0.4.0)

- **AI는 드라이브 폴더 목록을 알 수 없다.** `server/drive.js` `DRIVE_AI_ENABLED = false` — MCP 드라이브 도구(아래 3개)를 등록하지 않고, `/api/drive/ai-context`·`/api/drive/proposals/*` 는 403 `DRIVE_AI_DISABLED`. 화면의 'AI 사용 설정'·'AI 첨부'도 숨긴다. 소스는 다시 켤 때를 위해 남긴다.
- **폴더 목록은 내 화면에만 보이며 서버에 저장되지 않는다.** 서버는 확장이 보낸 목록을 메모리에서 요청한 화면에 한 번 건네고(`GET /api/drive/jobs/:id` → `deliver`) 지운다. `/api/drive` 작업 목록에는 목록을 싣지 않는다. 예전에 디스크(`index.json` context)에 남은 목록은 읽을 때 지운다. 휴대전화처럼 확장이 없는 기기도 볼 수 있도록 PC 확장 → 서버 메모리 → 화면으로 중계한다(디스크 저장 없음).
- **가져오기·업로드·교체·삭제·이름 바꾸기는 본인이 cowork 화면에서 직접 할 때만** 실행한다. AI 는 드라이브 작업을 요청할 수 없다.
- **쓰기(업로드·교체·삭제·이름 바꾸기)는 개인 프로젝트에서만.** 서버는 사용자별 연결에 등록한 프로젝트 ID와 비교하고, 확장은 현재 탭 주소·API 응답의 프로젝트 ID·개인 드라이브 유형을 작업마다 검사한다. 공유 프로젝트는 허용하지 않는다.
- **삭제 = 두레이 휴지통으로 옮김**(`POST /drive/v1/drives/{driveId}/files/{fileId}/move` `{destinationFileId:'trash'}`), **이름 바꾸기** = `PUT /drive/v1/drives/{driveId}/files/{fileId}?media=meta` `{name}` — 같은 폴더에 같은 이름이 없고 목록에서 본 revision 이 그대로일 때만. 두레이 공개 API 경로를 웹 로그인 쿠키로 부르는 것이며 **실제 두레이에서는 아직 확인하지 않았다**(첫 사용 때 시험 파일로 확인). 확장 0.4.0 미만이면 서버가 409 `DRIVE_BRIDGE_OLD`.
- 시험: `tests/drive_privacy.test.mjs`(`npm run test:drive` 에 포함).

## AI 접근 (꺼 둠 — DRIVE_AI_ENABLED=true 일 때만)

사용자가 **AI 사용 설정 → 현재 폴더 목록을 AI에 보여주기**를 켜야 현재 폴더의 한 쪽이 MCP에 표시된다. 폴더를 바꾸면 허용이 해제된다. 폴더 이름·파일 이름은 자료로 처리한다.

- `get_drive_context`: 허용된 현재 폴더 한 쪽과 개인 서버 보관 파일 목록. 전체 드라이브 검색·순회 기능 없음.
- `prepare_drive_file(doc_id, attachment_id?)`: 공동 기준 HWPX 또는 해당 문서에 저장된 첨부·AI 결과 파일을 개인 서버 보관함에 준비. 바이트는 AI를 통과하지 않음.
- `propose_drive_upload(staged_id, name?, replace_id?, reason)`: 현재 허용 폴더에 업로드할 제안을 저장. 사용자가 드라이브 화면의 AI 사용 설정에서 확인하고 실행. 다른 프로젝트·폴더는 지정할 수 없음.

## 운영·검증

브라우저 연결 토큰은 cowork 일반 사용자 토큰과 분리한다. 서버는 토큰의 해시만 메모리에 두고, 연결 해제·서버 재시작 시 무효화한다. 두레이 로그인 정보는 서버에 보관하지 않는다.

전송 작업은 한 번 선점하며 3분 후 종료 처리한다. 결과가 불명확할 때 원격 쓰기를 자동 반복하지 않는다. 연결 해제 시 이미 네트워크로 전송 중인 작업까지 취소되었다고 보장하지 않으므로 원격 파일을 확인한다.

검증은 `npm run test:drive`와 MCP·세션·연결 UI 회귀 시험으로 수행했다. 실제 두레이 시험은 **개인 프로젝트/test** 폴더에서 새로 만든 `cowork-drive-test.txt`, `cowork-drive-bridge-test.txt`, `cowork-ui-upload-test.txt`만 업로드·교체했다. 원래 있던 다른 파일은 수정하지 않았다. 시험 서버는 임시 데이터·별도 포트로 띄웠다. 사용자 data/와 config.json은 시험에 쓰지 않았다.

실제 로그인된 두레이에서 어댑터의 목록·업로드·다운로드·교체·revision 충돌, cowork UI와 브리지 프로토콜을 연결한 파일 왕복을 확인했다. 0.2.0에서는 설치된 Brave 실행 파일의 임시 프로필로 확장을 로드하고 Google identity API를 제공하지 않는 조건을 주입해 초기화 실패를 재현했다. 수정 후 같은 조건에서 서버 연결·폴링과 실제 scripting API의 오류 반환이 작동하는 것을 검증했다. 브라우저 잠금 API가 없는 조건도 확인했다. 사용자 Brave의 로그인·쿠키·보안 설정은 변경하지 않았다.

문서함 연동은 임시 서버에서 비공개 기본값, 개인/공용 폴더 지정, 권한 변경 뒤 저장 거절, 볼 수 없는 문서의 전송 준비 차단을 검증했다. 화면에서도 개인 폴더 가져오기(다른 계정 404), 공용 폴더 가져오기(다른 계정 열기 가능), 문서함 문서 전송 준비를 확인했다. 이 수정 검증 중에는 실제 두레이 파일을 추가로 변경하지 않았다.

탐색기 화면 개편은 임시 서버와 모의 드라이브로 자동 연결, 폴더 이동·검색, PC 업로드·바이트가 동일한 다운로드, 개인/공용 폴더 가져오기와 계정별 접근, 편집함 문서 업로드, 임시 사본 정리, Esc·초점 복귀를 확인했다. Brave 임시 프로필에서 실행 오류 없이 화면을 열고 데스크톱·390px 화면을 확인했으며 편집기의 335px 패널에서도 가로 넘침 없이 작동했다. 이 UI 개편에는 확장 업데이트나 서버 재시작이 필요 없고 cowork 페이지를 새로고침하면 된다.

참고: [브라우저 출처 정책](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy), [Chrome 확장 실행 스크립트](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts).
