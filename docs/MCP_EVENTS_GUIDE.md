# HWPX 새 요청 자동 검토 — MCP Events

2026-10-26. 설치 없이 본인의 ChatGPT Work가 새 HWPX 요청을 받아 처리하도록 하는 기능이다.

> **2026-10-28 — 참여자 안내에서 뺐다.** 반응이 느리고 조직 권한상 막아 두어 사용 설명서·MCP 안내(instructions)에서 이벤트 구독·예약 점검 안내와 상태 단추를 지웠다. 서버의 이벤트 기능 코드는 그대로 두었다(이 문서는 운영 참고용). 참여자는 ChatGPT 대화에서 “대기열을 처리해 줘” 또는 Codex 실행기·자동화를 쓴다.

## 선택한 방식

| 방식 | 역할 | 이 프로그램에서의 선택 |
|---|---|---|
| 일반 MCP + OAuth | 사용자가 대화에서 요청할 때 도구 사용 | 기존 기능 유지 |
| SSE/Streamable HTTP | 도구 응답과 기존 개인 실행기의 알림 전송 | 기존 Claude 채널·API 실행기용으로 유지 |
| ChatGPT 내부 SSE 위젯 | 열린 위젯에서 알림·후속 메시지 시도 | 자동 감시의 기본 방식으로 사용하지 않음 |
| MCP Events 웹훅 | 새 이벤트가 해당 Work 채팅의 작업을 시작 | 새 자동 검토의 기본 방식 |

OpenAI 공식 문서에서 MCP Events는 Work 웹 채팅, 데스크톱 Work + Cloud 및 dots에 제공된다. MCP 2.0(`2026-07-28`)이 필요하며 웹훅과 callback 검증을 지원한다. 이벤트 수신을 위한 polling/streaming은 지원하지 않는다. 일반 ChatGPT 대화에서 한 번 대기열을 조회하는 방식과 구분해야 한다. [공식 MCP Events 문서](https://developers.openai.com/plugins/build/mcp-events).

## 사용자 실행 순서

원본 첨부를 Work 자체 도구로 처리하고 생성 파일을 돌려받는 절차는 [Work 파일 교환 안내](CHATGPT_WORK_FILES.md)를 따른다. 사용자 PC 폴더·브리지는 필요 없다.

1. HWPX 웹과 ChatGPT 플러그인 OAuth에 같은 본인 HWPX 사용자로 연결한다. 참여자마다 다른 토큰을 사용한다.
2. ChatGPT의 해당 HWPX 플러그인 관리 화면에서 **Refresh / Rescan**으로 서버의 도구와 이벤트를 다시 읽는다. 서버 URL은 기존 HTTPS `/mcp` 주소를 유지한다. `ai_request.created` 이벤트가 표시되어야 한다.
3. **Work 채팅**을 연다. 데스크톱에서는 **Work + Cloud**를 선택한다. 작업공간에서 플러그인과 이벤트 작업이 허용되어 있어야 한다.
4. 플러그인을 선택하고 아래 지시를 한 번 보낸다.

> HWPX의 ai_request.created 이벤트를 구독해 줘. 내 새 대기열 요청이 도착할 때마다 get_request로 최신 attempt를 읽고, start_request로 맡은 뒤 제안과 요약을 남기고 complete_request로 완료해 줘. 본문은 직접 반영하지 마. 지금 대기 중인 내 요청도 한 번 처리해 줘. events/subscribe가 성공했는지와 구독 ID를 알려 줘. 대기열 조회만 하고 자동 감시가 켜졌다고 말하지 마.

5. 서버에서 `events/subscribe`와 callback 검증이 성공해야 구독이 생긴다. HWPX에 로그인하고 **사용 설명서 → 내 ChatGPT 연결 → 내 이벤트 구독 상태**를 눌러 활성 구독이 1개 이상인지 확인한다.
6. 같은 사용자로 HWPX 문서를 열고 새 AI 요청을 **대기열**로 보낸다. 이후 요청마다 ChatGPT에 메시지를 다시 보낼 필요가 없다. 새 요청 알림은 구독한 Work 채팅으로 전달되고 ChatGPT가 사용자의 구독 지시에 따라 작업한다.
7. HWPX AI 작업 탭에서 실제 제안·요약을 확인한다. 제안의 본문 반영은 사람이 결정한다.

중지하려면 해당 Work 채팅에서 “HWPX 이벤트 구독을 해제하고 자동 검토를 중지해 줘”라고 요청한다. 기존 OAuth 연결을 해제해도 그 연결로 만든 구독의 전송이 중단된다. 단순히 HWPX 웹에서 로그아웃하는 것은 이벤트 구독 해제가 아니다.

## 서버가 제공하는 프로토콜

- `server/discover`: MCP 2.0 버전·tools/events capability·서버 지침.
- `events/list`: `ai_request.created` 스키마. 선택 필터 `document_id`를 생략하면 모든 문서의 **본인** 새 대기열 요청을 감시한다.
- `events/subscribe`: 소유 사용자·필터·콜백으로 멱등 구독 ID를 생성한다. ChatGPT가 전달한 HTTPS URL·서명 키로 challenge callback을 검증한 뒤 저장한다.
- `events/unsubscribe`: 소유자에게만 해당 구독 해제를 허용하며 반복 호출도 안전하다.
- `tools/list`, `tools/call`: MCP 2.0의 요청 메타데이터/헤더를 검사하고 기존 도구 구현을 호출한다. 기존 `initialize` 기반 클라이언트도 계속 지원한다.

이벤트 payload에는 `document_id`, `request_id`, `attempt`, `kind`, HWPX 문서 URL만 들어간다. 지시 원문·문서 본문·첨부·사용자 토큰은 넣지 않는다. ChatGPT는 기존 `get_request`로 권한에 맞는 내용을 읽는다. 서버 AI나 다른 실행기가 이미 처리 중인 작업은 새 자동 검토 대상으로 보내지 않는다.

## 유지·전송·복구

구독 및 outbox는 데이터 폴더의 `mcp-events.json`에 원자적으로 저장한다. 구독의 서명 키가 포함된 비공개 운영 파일이므로 문서와 마찬가지로 데이터 폴더의 운영자 접근 권한과 백업을 관리한다.

새 요청·다시 요청 시 즉시 전송을 깨운다. 서버 내부의 복구 점검은 재시작이나 잠깐의 알림 누락 후 아직 대기 중인 요청을 다시 확인한다. 이는 ChatGPT의 이벤트 polling이 아니다. 이미 완료·취소·다른 실행기가 선점한 작업을 뒤늦게 새 작업으로 보내지 않는다.

구독은 기본 최대 24시간씩 허용하고 ChatGPT가 만료 전에 갱신한다. `ttlMs`가 있으면 최대 24시간, 최소 1분 범위로 허용한다. 무기한 요청에도 유한한 갱신 기한을 반환한다. `cursor`는 `null`이며 프로토콜을 통한 과거 전체 이벤트 재생은 제공하지 않는다. 구독 전부터 쌓여 있던 요청은 최초 구독 지시에서 한 번 처리하도록 요청한다.

전송은 Standard Webhooks HMAC 서명을 사용한다. 동일 이벤트의 재전송은 이벤트 ID와 본문을 유지하고 전송 시각·서명을 새로 만든다. 일시 오류는 지수 간격으로 최대 6회 시도한다. `410`·`413`에는 재시도하지 않으며 `410`이면 구독을 비활성화한다. 서버 재시작 후 대기 중인 outbox를 이어 전송한다. 수신 확인 `2xx`는 ChatGPT가 이벤트를 받았다는 뜻이며, AI 검토 완료는 HWPX 요청 상태로 별도 확인한다.

사용자 토큰 변경·사용자 삭제·OAuth 해제·구독 만료·공유 주소 변경 후에는 해당 구독의 전송을 중단한다. 구독 갱신 시 키가 바뀌면 짧은 회전 기간 동안 이전/새 키 서명을 함께 보낸다.

콜백은 HTTPS만 허용한다. DNS를 **실제 연결 시마다** 검사하고 사설·루프백·예약 IP를 차단한다. 검증한 IP로 연결하되 원래 호스트명으로 TLS 인증서를 검증하며 리디렉션은 따라가지 않는다. 이 검사는 challenge와 실제 이벤트 전송 모두에 적용된다.

## 운영 확인

웹 **내 이벤트 구독 상태**에서 활성 구독과 전송 대기·수신 확인·실패 수를 본다. 상태가 0개이면 자동 감시가 켜진 것이 아니다.

`npm run test:events`로 callback 검증·서명·필터·멱등성·재시작·재시도·해제·권한·MCP 2.0 도구 회귀 시험을 실행한다. 임시 서버와 가짜 callback을 사용하므로 실제 사용자 요청이나 유료 모델 호출은 발생하지 않는다.

최종 확인은 실제 Work 채팅에서 **구독 성공 → 새 요청 → 웹훅 2xx → 해당 채팅의 검토 실행 → HWPX 결과 저장**까지 진행한다. 서버 코드가 준비된 것만으로 특정 계정의 이벤트 권한이나 구독 성공을 가정하지 않는다.
