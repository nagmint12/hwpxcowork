브라우저의 사용자 정의 클립보드 형식은 `web ` 접두어와 별도 OS 매핑을 사용합니다. 한글이 쓰는 임의의 등록 형식 `Hwp Native`에 브라우저가 직접 쓸 수 있는 API가 아닙니다. 따라서 Rust를 WASM으로 빌드해도 이 제한을 해제하지 못합니다. 원격 서버에 Rust 프로그램을 넣어도 클라이언트 PC의 OS 클립보드에 접근할 수 없습니다.

## 한글 2018·2022 → 웹 원본 가져오기 (2026-11-01)

Windows 서버에서 `clipboardBridge.enabled: true`를 설정하면 서버가 `scripts/hancom-clipboard-bridge.py --watch`를 숨겨 실행합니다. 설치된 Python에는 `pywin32`가 필요합니다. 도우미가 종료되면 자동 재시작하며, 서버의 정상 종료에는 함께 종료합니다. 다른 클라이언트 PC에서는 해당 PC에 같은 도우미를 실행해야 합니다. 명령줄로 실행할 때 표준 입력을 유지하고, 종료하려면 `stop`을 입력합니다.

도우미는 설치된 한글 프로세스의 새 복사만 처리합니다. 한글 실행 파일 버전으로 2018·2022를 구분하고, 원래 네이티브·HTML·텍스트·RTF·문서·그림 형식을 보존하며 HTML 조각 안에 원본 바이트를 함께 넣습니다. 기존 OLE 지연 데이터는 정적 데이터로 구체화하므로 복사한 한글 창을 닫아도 브라우저가 같은 원본을 받습니다. 실행 전 클립보드나 다른 앱의 복사를 소급 처리하지 않습니다.

웹은 일반 Ctrl+V의 붙여넣기 이벤트로 전달받은 바이트만 `/api/clipboard/import`로 보냅니다. 로그인과 같은 출처를 검증하며, 공용 접속에 서버 클립보드 읽기를 허용하지 않습니다. 숨은 별도 한글이 보안 모듈을 등록한 뒤 HWP→HWPX로 변환합니다. 원본 블록은 32MiB까지이며 변환은 한 번에 하나씩 처리합니다. 변환 중 사용자가 글·커서를 바꾸면 지연 붙여넣기를 취소합니다.

빈 문단에는 첫 원본 문단의 스타일과 직접 지정한 줄 간격·들여쓰기까지 가져옵니다. 기존 글 중간에 붙이는 경우에는 대상 문단의 문단 서식을 유지합니다. 서버 저장에서도 본문에 직접 쓰이지 않은 문자 스타일·다음 스타일을 함께 보존합니다. 새 그림에는 기존 그림 교체용 크기 보정을 적용하지 않으며, 표 안에 실린 메모를 별도로 다시 삽입하지 않습니다.

실제 한글 2018(10.0.0.6415), 2022(12.0.0.3146)의 복사 8종과 브라우저 Ctrl+V·자동 저장을 검증하고, 회전 꼭짓점을 갖는 추가 2종도 확인했습니다. 문제문서, 표·새 스타일·메모, 회전·묶음 도형, 셀 안 일부 글의 복사를 각각 두 버전으로 확인했습니다. 독립 한글 변환본과 글자별 서식·문단 모양, 스타일 정의, 표/셀 구조·테두리/배경, 그림 원본 바이트·위치·치수, 도형 회전·행렬·곡선 구간을 비교했습니다.

**남은 화면 표시 차이:** 원본 곡선 구간과 회전 꼭짓점은 저장되지만, 현재 렌더러는 일부 곡선을 직선으로 표시하고 일부 회전 사각형의 화면 크기를 다르게 그립니다. 원본 데이터 보존과 화면의 완전한 일치는 구분해야 합니다. OLE/차트·글맵시 등도 이번 실제 복사 시험에 포함하지 않았습니다. 상세 결과와 비교 이미지: [검증 보고서](../artifacts/hancom-native-import-20261101/VERIFICATION.md).

### 바탕쪽 배경·구역 설정 (2026-10-29)

증상: 기관 마크·UIC 마크가 있는 쪽 배경(바탕쪽 그림)을 쓰는 문서를 모두 복사해 한글에 붙이면, 배경 자리에 표지의 기관 글자 로고와 UIC 마크가 쪽 크기로 늘어나 붙었다. **문서 오류가 아니라 엔진 결함**이었고, 한글로 다시 저장한 문서와 한글에서 새로 만든 바탕쪽 문서에서도 똑같이 일어났다(바탕쪽이 없는 새 문서는 정상).

- 원인 1 — 바탕쪽 그림 참조(`bin_data_prune.rs`): 복사 조각을 만들며 쓰지 않는 그림을 지우고 번호를 당기는데, 바탕쪽은 문단이 아니라 `Section.section_def` 에 있어 참조를 세지 않았다. 바탕쪽 그림 1·2 가 지워지고 본문 그림 3·4(기관 로고·부서 마크)가 1·2 로 당겨져, 바탕쪽이 그 로고를 쪽 크기로 그렸다. 바탕쪽 목록도 같이 훑도록 고침(발췌 저장도 같은 함수를 씀).
- 원인 2 — 부분 복사의 구역 정의(localhost `Hwp Native`): 조각이 원본 구역 정의(쪽 설정·바탕쪽)를 그대로 실어, 빈 문서에 붙이면 받는 쪽 구역 설정과 바탕쪽을 덮었다. 한글은 **모두 선택한 복사에만** 원본 구역 정의를 싣고, 구역 첫머리부터 일부만 복사해도 '새 문서' 기본값이다(실측). 부분 복사 조각은 새 문서 구역 정의(바탕쪽 없음, 59528×84188)를 싣는다.

## Alt+C 사용법과 범위

1. 원본 글자 **뒤**에 커서를 놓고 Alt+C 또는 모양 복사 도구를 누릅니다. 문단 시작에서는 첫 글자의 모양을 사용합니다.
2. 글자 모양 / 문단 모양 / 둘 다 / 글자 스타일 / 문단 스타일 중 선택하고 **복사**합니다.
3. 대상 글을 블록으로 선택하고 Alt+C를 누릅니다. 적용창 없이 바로 바뀝니다. 표 칸 블록도 지원합니다.
4. 다른 부분을 선택하고 Alt+C로 계속 적용합니다. 새 원본은 선택을 해제한 위치에서 Alt+C로 다시 복사합니다. 취소하면 이전 모양을 유지합니다.

글자 모양은 선택된 글자 범위에, 문단 모양은 걸쳐 있는 문단에 적용합니다. 문단 스타일은 스타일 이름·기본 글자 모양·문단 모양을 적용합니다. 원본의 직접 지정 모양을 옮기려면 글자/문단 모양이나 ‘둘 다’를 선택합니다. 글자 스타일은 엔진에서 현재 글자 모양과 일치하는 스타일 정의가 확인된 경우 활성화됩니다. 머리말·꼬리말·각주에서 원본을 취득하는 기능과 표 자체의 칸 여백·테두리 복사 옵션은 이번 범위에 포함하지 않습니다.

본문·표 칸·캡션을 지원하며 중첩 표 경로도 엔진 주소 체계를 사용합니다. 글꼴·탭·문단 테두리·번호 참조는 대상 문서의 번호로 재매핑합니다. 문서 전체 기본 탭 간격·용지 설정은 변경하지 않습니다. 여러 문단의 ‘둘 다’ 적용도 실행 취소 한 번으로 되돌립니다. 모양 버퍼는 일반 Ctrl+C와 별개이며, 현재 탭 세션과 같은 출처의 열린 탭에서 공유됩니다.

단축키/원본 위치/반복 적용 기준: [한컴 모양 복사 도움말](https://help.hancom.com/hoffice/multi/ko_kr/hwp/format/quick_format/quick_format.htm).
