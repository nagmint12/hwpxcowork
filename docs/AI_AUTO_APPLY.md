# AI 자동 반영과 편집기 갱신

문서 설정에서 **AI 자동 반영 → 자동 반영**을 고르고 저장하면, 다음 AI 작업부터 완료 시점에 권장안을 문서에 반영한다. 기본값은 **직접 반영**이며, 설정을 켜는 것만으로 기존 대기 제안이나 완료된 작업을 소급 반영하지 않는다.

- 글 수정, 서식, 문단·표·그림 삽입과 그림 교체에 같은 옵션을 사용한다. MCP·개인 실행기와 서버 AI 모두 공통 서비스에서 처리한다. 요청에 묶이지 않은 AI 제안은 생성 시 반영한다.
- 작업 중에는 AI가 읽은 원문을 유지하고, 완료 시 문서 뒤쪽·글 뒤쪽부터 일괄 반영한다. 여러 비교안은 자동 선택하지 않는다.
- 반영 순간의 문서 설정·사용자 수정 권한·직접 반영 권한·서버의 에이전트 적용 허용을 확인한다. 승인 방식의 직접 반영 제한도 유지한다. 제한된 결과는 대기로 남는다.
- 작업 중 옵션을 끄거나 수정 권한을 철회하면 완료되어도 자동 반영하지 않는다. 취소되거나 시도가 바뀐 작업에는 기존 요청 검사를 적용한다.
- 원문이 바뀌어 반영할 수 없는 항목은 대기 상태와 오류 기록을 남긴다. 다른 유효한 항목은 처리한다. 문서를 일부 변경한 뒤 실패하면 기존 트랜잭션 규칙에 따라 전체를 되돌린다.
- 자동 반영한 제안도 기존 되돌리기를 사용할 수 있다. 동일한 작업 완료 호출을 반복해도 중복 적용하지 않는다.

REST 설정 키는 `aiApply: "manual" | "auto"`이다. 서버 기본값을 지정할 때는 `documents.defaultAiApply`을 사용할 수 있다. `autoApplied`와 `autoApplyError`는 각 제안에 남고, 활동 기록은 `proposal.autoApply`·`proposal.autoApplyFailed`를 사용한다. 설정 권한과 저장·WebSocket 전파는 기존 문서 설정과 같다.

텍스트 변경은 기존 문단 단위 동기화를 사용한다. 그림 교체는 본문 텍스트가 같아도 파일과 크기가 바뀌므로, 그림·표의 반영·되돌리기를 `formatVersion`과 `formatting: true` 알림으로 전파한다. 편집기는 이 신호로 원본 HWPX를 다시 읽으며 저장하지 않은 글을 먼저 보내고 스크롤·선택 범위를 복원한다. 페이지 전체 새로고침은 하지 않는다. 연결이 끊겨 알림을 놓쳐도 다시 받은 문서 정보의 `formatVersion`으로 감지한다.

이 갱신은 기존 편집기 로딩 경로를 사용한다. 그림 하나만 엔진 안에서 교체하는 별도 기능은 추가하지 않았으며, AI를 다시 호출하거나 추가 API 토큰을 사용하지 않는다.

검증: `node --test tests/ai_auto_apply.test.mjs tests/view.test.mjs tests/figure_replace.test.mjs`. 실제 브라우저의 설정 저장·그림 픽셀 변경·선택 범위 보존 결과는 `artifacts/ai-auto-apply-20261030/ui-result.json`에 기록했다. 실제 사용자 문서·설정은 시험에 사용하지 않았다.
