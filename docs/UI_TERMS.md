# 화면 글·용어 기준 (2026-10-29)

문서 화면(web/)의 보이는 글은 이 표를 따른다. 사용자 요청(2026-10-29): 글이 너무 많고 문장투라 지저분하다 — 설명은 `?`·마우스 올림(title)으로, 비슷한 선택지는 하나로, 같은 정보를 두 번 쓰지 않는다, 어려운 용어(기준·에이전트·해결)는 쉬운 말로.

## 1. 화면 원칙

1. **보이는 글은 이름표만.** 단추·칩·제목은 2~6글자 명사/동사. 설명 문장은 `title`(마우스 올림) 또는 `?` 도움말(`Hint` — 누르면 사용 설명서 그 절)로 옮긴다. 예외: 오류·경고·빈 목록 안내(한 줄, 짧게).
2. **한 번만 말한다.** 같은 카드·줄에 같은 뜻을 두 번 쓰지 않는다. `AI 작업 #3` 옆에 `AI 검토`·`지시`·`다듬기` 같은 종류 이름을 또 붙이지 않는다(종류는 `#3` 의 title 로). 자동 요약 `AI 검토 요청 — AI 처리 대기`처럼 상태를 되풀이하는 글은 보이지 않는다(사람·AI 가 쓴 요약만).
3. **상태는 하나.** AI 작업 하나의 진행은 칩 하나로: `대기열` → `전달됨` → `처리 중` → `확인 필요`(AI 가 끝냈고 사람이 반영·거절할 제안이 남음) → `완료`, 그 밖에 `실패`·`취소됨`. 보낸 곳(환경 이름)·맡은 사람·시각은 그 칩의 title 에.
4. **선택지는 적게.** 차이가 작은 선택지는 합친다(아래 §3). 상황에만 쓰는 것은 그 상황에서만 보인다.
5. **안내 상자를 화면에 펼쳐 두지 않는다.** 연결 방법·MCP 주소·실행기 안내 같은 것은 사용 설명서(`/help.html`)에 있다 — 화면에는 `?` 하나.
6. **두 칸.** 넓은 화면은 문서 | AI 작업 창. 메모는 한글처럼 문서 옆 여백에 띄우고(끌어 옮김), AI 작업 창은 꼭지로 접고 편다 — 자리 바꾸기 같은 선택지를 따로 늘어놓지 않는다(V4_SPEC §5).

## 3. AI 요청 종류(요청 창)

- 기본 선택지는 둘: **요청**(자유 지시 — 비워 두면 검토만) · **다듬기**(간결하게·공문서체로·맞춤법·쉽게·사실 확인).
  - `요청` = 예전 `AI 검토` + `지시`. 지시·첨부가 없으면 서버 종류 `review`(검토), 있으면 `instruct` 로 보낸다(서버·MCP 종류는 그대로).
- 상황 종류(문장 제안·표 채우기·표 만들기·문단 추가)는 우클릭 메뉴에서 그 종류로 열었을 때만 세 번째 칩으로 보였다 — 2026-11-03 메뉴를 하나로 합쳐 이제 열 길이 없다(아래).
- **메뉴에서 요청 종류를 고르지 않는다**(2026-11-03 사용자 요청 — 사람이 상황에 맞춰 메뉴를 고를 까닭이 없고 AI 가 지시·문맥을 보고 도구를 고른다). 우클릭 '검토' 구역 = (덮는 제안·수정 중·메모) → `AI에게 맡기기…` · `AI에게 빠르게 맡기기 ▸` → `메모 달기`. 선택 도구 막대 = [AI에게 맡기기] [AI에게 빠르게 맡기기 ▾] | [메모]. 둘 다 요청 종류 `instruct`.
  - `AI에게 맡기기…` = 요청 창(비워 두면 검토).
  - `AI에게 빠르게 맡기기` = 예전 'AI 빠른 작업'과 같은 자리·이름·순서(검토하기 · 문장 고쳐 쓰기 · 구분선 · 다듬기 기준). 누르면 알맞은 **예시 지시**를 넣은 요청이 된다(지시 글 `web/menumodel.js` `quickTasks`·`QUICK_POLISH_PROMPTS` — 서버 설정의 다른 다듬기 기준은 이름표로 지시를 만든다). 문서 설정 `AI에게 빠르게 맡기기`(aiQuick)가 바로 보내기(기본)면 곧바로 보내고, 확인 후 보내기면 예시 지시를 넣은 요청 창을 연다.
  - 첨부해서 요청·표 채우기·뒤에 문단 추가·뒤에 표 만들기 항목은 없앴다 — 자료는 요청 창에 첨부하고, 문단 추가·표·여러 안 비교는 지시에 적는다.
- 종류 설명은 칩의 title(마우스 올림).

## 4. 색·모양 구분 (2026-10-29)

사용자 요청: 누르면 바로 AI 에게 가는 단추와 확인하고 눌러야 하는 단추를 다른 단추와 구별하되 과하지 않게.

- **보라 ✦ = 누르면 AI 에게 바로 보냄.** 요청 창 [보내기](보라 채움), AI 작업의 [다시]·[다시 요청](보라 테두리·글자), 바로 보내기일 때의 'AI에게 빠르게 맡기기' 항목(검토하기·문장 고쳐 쓰기·다듬기 기준). 화면은 `button.ai-send`(web/style.css), 편집기 안은 `cw-send`(studio/plugin/style.ts — 어두운 화면 `data-theme-effective="dark"` 에서는 연보라 `--cw-ai-text` #d0bfff·`--cw-ai-icon` #b197fc, 글자 대비 4.5:1 이상). 요청 창을 여는 것([AI에게 맡기기]·'AI에게 맡기기…')은 표시하지 않는다 — 문서 설정이 '확인 후 보내기'면 빠르게 맡기기도 표시하지 않는다.
- **보낼 곳은 이름표로 한 번.** 바로 보내는 목록 맨 위에 머리글 `Claude Code로 보내기`·`Codex로 보내기`·`API로 보내기`(연결된 AI 가 없으면 `대기열에 넣기`) — 자동 경로(채널 → 내 AI 키 → 대기열, `util.workEnv`·`sendToLabel`). [다시]는 단추 글은 그대로, 보낼 곳은 title(`같은 요청을 Claude Code로 다시 보냅니다`).
- **옅은 초록 ✓ = 확인하고 누를 일.** 메모의 [완료](AI 의견 포함)·변경 요청 의견의 [완료] — `button.ack`. 누른 뒤 [다시 열기]는 보통 단추.
- **선택 도구 막대는 세 단추**: [AI에게 맡기기] [AI에게 빠르게 맡기기 ▾] | [메모](2026-11-03 — 옛 [AI 요청] [AI 빠른 작업 ▾] | [메모]). 빠르게 맡기기 목록은 우클릭 'AI에게 빠르게 맡기기 ▸'와 같은 이름·순서.
- 파랑 채움(primary)은 그 밖의 주 동작([모두 반영]·[검토 요청] 등) 그대로.

## 5. 바꾸지 않는 것

- 서버가 만드는 한글 메모 글(server/memotext.js)·MCP 도구 이름·REST 필드·종류 id(`review`·`instruct` …)·`data-testid`.
- 코드 주석의 옛 용어(고칠 때 함께 고치면 좋지만 필수 아님).

## 6. AI 작업 진행 단계 색·움직임 (2026-10-30)

사용자 요청: 서버에 보냈는지, 처리하고 있는지, 도착해서 내가 반영·확인해야 하는지가 한눈에 들어오지 않는다.

진행 단계 하나(`web/ui.js` `requestPhase`)를 상태 칩·카드·꼭지/탭 수·편집기 강조가 같이 쓴다(클래스 `ph-…`, 편집기 안 `cw-ph-…`). 칩 글(§1-3)은 그대로다.

| 단계 | 언제 | 모양 |
|---|---|---|
| `wait` 응답 대기 | 대기열·전달됨(아직 AI 가 맡지 않음) | 은은한 붉은 톤: 칩 테두리·빈 점, 카드 왼쪽 띠·아주 옅은 바탕, 편집기 붉은 점선 밑줄 |
| `late` 응답 없음 | 2분(`LATE_MS`) 넘게 맡는 이 없음, 맡은 시간 지남 | 위보다 조금 짙게(칩 점이 참) — title 에 'n분째 응답 없음' |
| `run` 처리 중 | AI 가 맡아 일하는 중 | 보라 + 움직임(Gemini 같은 흐르는 빛): 카드 왼쪽 띠에 파랑·보라·분홍 빛이 흐르며 번쩍이고, 카드 위로 빛이 비스듬히 지나가며 둘레가 보랏빛으로 숨쉬고, 위쪽 가장자리에 빛줄. 칩 점 숨쉬기, 결과 창 세 점, 편집기 강조가 숨쉬듯 |
| `act` 내 차례 | 끝났고 내가 반영·거절할 제안이 남음 | 파란 테두리 강조(도착하면 두 번 번짐). 내 요청의 대기 제안 카드·AI 의견 메모도 같은 테두리(종류 띠 색은 그대로) |
| `hold` | 남은 제안이 있지만 남의 요청 | 강조 없음(옅은 파랑 칩) |
| `ok` · `fail` · `off` | 완료 · 실패 · 취소됨 | 초록 · 빨강(채움 — 응답 대기의 옅은 붉은 톤과 구별) · 회색 |

- **한눈에 보는 수**: 꼭지 [AI 작업]·패널 탭 'AI 작업'·AI 작업 목록 머리에 `확인 n`(파란 테두리) · `처리 중 n`(보라) · `대기 n`/`응답 없음 n`(붉은 톤) — 0 인 것은 숨김(`requestGlance`). 내 차례가 있으면 접힌 꼭지 자체에도 파란 테두리. 목록 머리의 수를 누르면 그것만 거른다(거르기 칸과 같은 값).
- AI 송수신 상태의 움직임(카드·상태 점·결과 대기·처리 중 수·편집기 강조)은 사용자 요청에 따라 '동작 줄이기'(prefers-reduced-motion) 설정에서도 재생한다(2026-10-31).

## 7. AI 작업 진행 기록 (2026-11-10)

사용자 요청: 처리 중에 AI 가 지금 무슨 일을 하는지(문서를 읽는지, 제안을 쓰는지) 실시간으로 알고 싶다.

AI 가 요청을 처리하며 부른 도구를 서버가 한 줄씩 남겨(`server/activity.js`) AI 작업 카드에 보인다(`web/ui.js` `RequestActivity`). 상태 칩(§6)은 그대로다.

| 자리 | 보이는 것 |
|---|---|
| 지금 줄(처리 중에만) | 마지막 단계 글 + `→ 생각 중 n초`(도구를 부르지 않는 동안 — 그 사이 AI 는 생각하거나 글을 쓴다. 그 내용은 서버가 볼 수 없어 시간만) |
| `작업 기록 n`(펼침) | 채팅처럼 차례대로: 시각 · 단계 글. 같은 단계가 이어지면 한 줄(`의견 남김 ×8`), 앞 단계와 3초 넘게 벌어지면 `+n초`. 끝나면 머리에 걸린 시간(`작업 기록 16 · 3분 35초`) |

- 단계 글은 낱말과 수·범위만 쓴다: `요청을 맡음` · `문서 읽기 · 본문 0~182번 문단(모두 387개)` · `문서 검색 · 3곳` · `서식 확인 · 문단 2개` · `수정 제안 20건` · `의견 남김` · `차례 새로 고침` · `그림 미리보기` · `완료`. 안 된 호출은 `— 안 됨(오류 코드)`. 문서 글·지시·검색어·파일 이름은 넣지 않는다(문서를 보는 사람 모두에게 보인다).
- AI 작업 탭 카드: 처리 중에는 펼쳐 두고, 끝나면 접는다(누르면 펼침). 본문 옆 카드(레일): 처리 중에만 지금 줄과 접힌 기록.
- 서버가 보지 못하는 것은 보이지 않는다: AI 의 생각 내용, 에이전트가 제 PC 안에서 하는 일(파이썬 실행·지침 파일 읽기). 기록은 서버 메모리에만 있어 서버를 다시 띄우면 사라진다(제안·의견·이력은 문서에 남는다).

## 8. 문단 주소와 제안 카드의 자리 (2026-11-10)

사용자 요청: 반영한 제안 카드의 주소(`s0/p655`)가 실제로 들어간 곳과 맞지 않는다 — 어디에 반영됐는지 정확히 보고 싶다.

- 문단 주소 `s0/p655` 는 문단마다 붙은 고유 번호가 아니라 **구역 번호 / 그 구역에서 위에서부터 센 본문 문단 차례(0부터)** 다. 한/글 파일의 문단에는
  믿을 고유 번호가 없어(`hp:p id` 는 거의 모든 문단이 같은 값) 차례로 가리키고, 문단을 넣거나 지우면 서버가 저장해 둔 주소를 다시 매긴다.
  표·글상자 안 문단은 `s0/p3/n5`(4번째 문단 안의 6번째 문단).
- 제안 카드의 주소 칩(`web/proposal-place.js`)은 **지금 그 제안이 가리키는 문단**을 보인다:

| 제안 | 반영 전·거절·되돌림 | 반영 뒤 |
|---|---|---|
| 문단·표·그림 넣기 | 그 뒤에 넣을 문단 + `이 문단 뒤에 새 문단` | 실제로 넣은 문단 + `넣은 문단`(여러 문단이면 `넣은 문단 n개`) |
| 바꿈·서식·표 고치기·그림 교체 | 고칠 문단 | 고친 문단(문단을 나눈 바꿈은 누르면 나뉜 끝 문단까지 깜빡임) |

- 칩을 누르면 편집기가 그 문단으로 가서 깜빡인다. 칩에 마우스를 올리면 `위에서 687번째 문단 「글 머리…」` 로 풀어 보인다(주소는 0부터, 풀이는 1부터).
- 그 문단이 그 뒤 지워졌으면 칩 대신 `자리 없음`.
- 같은 문단 뒤에 여러 개를 넣는 제안은 반영 전에는 모두 같은 주소다(차례로 쌓여 들어간다) — 반영하면 넣은 문단마다 제 주소가 된다.
