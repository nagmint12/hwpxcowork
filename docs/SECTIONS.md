# 구역을 넘는 편집 — 정의와 계약 (2026-10-29)

편집기(rhwp)·서버(engine/·server/)·플러그인이 구역(section)을 넘는 선택과 편집을 **한 가지 정의로** 다룬다. 목표는 한/글 2022 와 같은 결과다.
기준은 한/글 COM 실측(`tests/fixtures/sections/` — 두 구역 문서 `base.hwpx` 와 같은 편집을 한/글에서 한 결과 `hangul_*.hwpx`, 한/글 자체 복사의
클립보드 문서모델 `hangul_clip_*.json`), 시험은 `tests/sections.test.mjs`(`npm run test:sections`).

## 1. 정의

- **구역** = HWPX `Contents/sectionN.xml` 하나 = rhwp `document.sections[N]` = 주소 `sN/pM` 의 N. 구역마다 구역 정의(용지·여백·방향·바탕쪽·쪽 테두리·
  각주 모양·시작 번호)가 하나다.
- **구역 나누기** = 구역 첫 문단 머리의 구역·단 정의(rhwp `SectionDef`+`ColumnDef` 컨트롤, HWPX 첫 run 머리의 `hp:secPr`+`hp:ctrl>hp:colPr`).
  **파일 안 구역 나누기**(한 구역 파일 가운데 문단 머리의 `hp:secPr` — 차례 '현재 문서의 새 구역'이 만든다)도 한/글에는 같은 구역 나누기다.
  rhwp 는 둘을 같은 꼴로 본다(`Paragraph::has_section_break` / 서버 `HwpxDoc.hasSectionBreak`).
- **본문 위치 차례** = (구역, 문단, 글자). 선택은 이 차례로 구역을 넘을 수 있다(모두 선택, Shift+이동, 끌기, F3 확장).

## 2. 한/글 실측 (기준)

| 편집 | 한/글 결과 |
|---|---|
| 구역을 넘게 골라 지우기 | 두 구역이 하나로 합쳐진다. **앞 구역 설정이 남고** 뒤 구역 정의(가로 용지·바탕쪽 등)는 사라진다 |
| 앞 구역 끝에서 Delete · 뒤 구역 첫머리에서 Backspace | 두 문단이 합쳐지며 구역 나누기도 지워진다(위와 같음). **묻지 않는다** |
| 구역을 넘는 일부 복사 → 다른 곳에 붙이기 | 넘는 구역 나누기가 **뒤 구역의 실제 정의째** 실려 붙인 자리에서 구역이 나뉜다. 붙인 자리 뒤의 글은 마지막으로 나뉜 구역에 든다 |
| 모두 선택 복사 → 빈 문서에 붙이기 | 구역 둘 모두 원본 정의 |
| 클립보드 문서모델(hwpjson) | 문단 사슬 하나에 구역 나누기 문단(`secd`+`cold`, `bf: 3`)을 끼운 꼴. 일부 복사의 첫 구역 정의는 '새 문서' 기본값, 넘는 구역 나누기는 원본 정의(메모 모양 참조 포함) |
| 잘라 내고 제자리에 붙이기 | 원래 문서 그대로(구역 둘) |
| 변경 추적 켜고 구역을 넘게 지우기 | 구역은 수락할 때까지 남고 지운 글·문단 끝(`deleteEnd paraend="1"`)이 변경으로 남는다 |

## 3. 편집기(rhwp) 계약

| 동작 | 처리 |
|---|---|
| 선택 하이라이트 | 구역마다 나눠 그린다(`getSelectionRects` 는 한 구역 안만 받는다) |
| 지우기(Delete·Backspace·잘라내기·글자/IME 치기·붙여 바꾸기·Enter·Ctrl+E·단어 지우기) | `deleteRangeAcross` — 사이 구역을 앞 구역에 합친 뒤(`merge_section_into_previous`, 뒤 구역 첫 문단의 구역 나누기를 뺀다) 한 구역 안 지우기. 되돌리기는 문서 스냅샷(구역 수까지 돌아온다) |
| 구역 첫머리 Backspace · 구역 끝 Delete · 파일 안 구역 나누기 문단 앞뒤 | 위 범위 지우기로 보낸다(되돌려도 선택은 만들지 않는다). 파일 안 구역 나누기 문단을 합쳐도 구역 정의가 문단 가운데 남지 않는다 |
| 복사(내부·HWPX 조각·한글 문서모델·HTML·글) | `copySelectionAcross` — 넘는 구역 나누기를 구역의 실제 정의(`section.section_def`, 바탕쪽까지)째 싣는다. 조각은 구역 파일 여럿, 한글 문서모델은 구역 나누기 문단을 끼운 사슬, HTML 은 구역마다 내보내 잇는다. 첫 구역 정의는 구역 처음~끝 구역 끝(모두 선택)일 때만 원본 |
| 붙이기(내부·다른 탭 조각·한/글에서 복사) | 실려 온 구역 나누기마다 그 자리에서 구역을 나눈다(`split_sections_at_breaks`). 캐럿 결과에 `secIdx` |
| 표 칸·머리말/꼬리말·각주에 붙이기 | 구역 나누기는 빼고 글만(칸에는 구역이 없다) |
| 글자 서식(진하게·글꼴·크기 등) | (구역, 문단)마다 적용·되돌리기 |
| 문단 서식·스타일·번호/글머리표·정렬·줄 간격 | 구역을 넘는 모든 문단 |
| 되돌린 뒤 선택 | 구역을 넘는 범위도 한 구역 안과 같게 되살린다 |
| 파서 | 구역 정의는 그 구역의 첫 구역 나누기 것(파일 안 구역 나누기가 앞 구역 설정을 덮지 않는다) |

## 4. 서버 계약

- **실시간 밀어 넣기**(`server/live.js`): 기준과 보낸 문서의 구역 수가 다르면 `diffDocs` 가 두 문서를 구역 0 하나로 이어 견준다(`flattenSections` —
  구역 나누기는 파일 안 `hp:secPr` 로 남는다). 구역 합치기는 구역 나누기 문단을 합치거나 지운 것, 나누기는 `hp:secPr` 를 넣은 것(object 덩어리)으로 나온다.
  서버는 지금 문서와 meta 주소(제안·요청·`liveTouch`·잠금 — `_remapSections`)도 이어 같은 규칙으로 적용하고, 짝 문단의 구역 나누기 유무를 보낸 문서와
  맞춘 뒤 보낸 문서의 구역 경계에서 구역 파일로 다시 나눈다(`splitSectionsAt` — 구역 파일·content.hpf 항목·spine·`secCnt`). 옮긴 필드 id 가 겹치면 새 번호,
  메모 스레드 열쇠(`s{구역}:f{필드 id}`)는 메모 id 로 따라간다. 실패하면 meta 를 되돌린다. 구역 구조가 바뀐 커밋은 서식 커밋(다른 창은 다시 연다).
- **구역 첫머리에 넣는 문단**(`insertParagraphAfter(sec, -1, …, { atStart: true })`): 새 문단이 맨 앞에 들고 구역 나누기는 새 첫 문단으로 옮긴다
  (종전에는 첫 문단 뒤에 들어가 순서가 뒤바뀌었다 — 문서 첫머리 Enter 등).
- **변경 추적**(`track: 'tracked'`): 구역·문단 경계는 추적하지 않는다(문단 지우기·합치기와 같은 정책) — 구역은 곧바로 합쳐지거나 나뉘고 글만 변경 추적으로
  남는다. 한/글은 구역 나누기 지움도 변경으로 남기지만(§2), 이 도구의 최종본·편집기 화면은 한/글에서 모두 수락한 결과와 같다.
- **변경 요청(승인 방식)**: 구역별 주소로 되돌린 덩어리(`realSectionHunks`)로 글·서식만 반영하고, 구역 구조는 `unsupported`('구역 수가 바뀌었습니다')로 알린다.
- **편집본 올리기**(`PUT /upload`): 구역 수가 다르면 409 `SECTIONS`(구역마다 글을 맞추는 방식이라 겹쳐 들어간다).
- **플러그인**: 본문은 구역을 넘어도 한 묶음(선택·AI 요청 범위의 refs 가 구역을 넘는다, 사각형도 구역마다). 메모 범위는 종전처럼 구역 안.

## 5. 남은 한계

- 파일 안 구역 나누기(차례 '새 구역')의 용지 설정이 앞 구역과 다르면 편집기 화면은 그 파일의 첫 구역 용지로 그린다(저장 파일·한/글은 맞다). 붙여넣기로
  들어온 구역 나누기는 구역 파일로 나누므로 해당하지 않는다.
- 한 번 밀어 넣는 사이에 구역 합치기와 나누기가 함께 일어나 구역 수가 같으면 구역별로 견주어 구역 경계가 옮겨지지 않을 수 있다(서버 = 편집기가 아니면
  편집기가 서버 문서로 다시 연다).
