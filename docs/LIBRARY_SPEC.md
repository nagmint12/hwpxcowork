# 문서함·폴더·접근 권한 (2026-10-29)

사용자 요청(2026-10-29): 문서 목록 화면에 폴더를 두고 문서를 폴더에 배치한다. 공용 문서함과 개인 문서함으로 나누고, 역할(관리자·편집자·보기)에 묶여 있던 권한을 **사람마다·폴더마다** 주는 구조로 바꾼다. 개인 문서함은 올린 사람만 보고, 폴더(또는 문서 하나)에 사람을 더해 공유한다. 공용 문서함은 폴더별로 작성·삭제·편집 권한을 사람에게 준다.

구현: `server/library.js`(폴더·권한 계산), `server/service.js`(문서 권한·옮기기·문서 권한·목록 거르기), `server/routes/library.js`(경로), `server/index.js`(문서 접근 문), `server/mcp.js`(MCP 접근 문), 화면 `web/library.js`·`web/library-model.js`·`web/library.css`·`web/app.js`(DocList). 시험 `npm run test:library`(API), `tests/library_view.test.mjs`(화면 모델, `npm test`).

## 1. 자료

- **폴더 목록** `<dataDir>/folders.json` 하나(원자적 쓰기). `{ version: 1, folders: [...], publicRoot: { acl } }`.
  - 폴더: `{ id: 'f…', name, parentId|null, space: 'public'|'private', owner(개인일 때 주인)|null, inherit: bool, acl: [{ name, perms }], createdBy, createdAt, updatedAt }`.
  - 파일이 망가졌으면 읽기만 하고 폴더 바꾸기는 500 `LIBRARY_BROKEN`(덮어써서 지우지 않는다).
- **문서의 자리**는 문서 `meta.json` 에: `space`('public' — 없으면 옛 문서, 공용) · `spaceOwner`(개인 문서함 주인) · `folderId`(없으면 문서함 맨 위). 폴더가 없어졌거나 다른 문서함의 폴더를 가리키면 그 문서함 맨 위로 본다.
- **문서만의 권한** `meta.access = { acl }`(없으면 폴더 권한 따름).
- 옛 데이터는 그대로 읽힌다: 폴더 파일이 없으면 폴더 없음 + 공용 맨 위 기본 권한, 옛 문서는 공용 맨 위.

## 2. 권한

| 권한 | 이름 | 뜻 |
|---|---|---|
| `read` | 보기 | 목록에 보이고 열어 읽는다. 메모·AI 요청을 남긴다(종전 '읽기 전용'과 같음) |
| `write` | 작성 | 그 자리에 문서를 올리고 하위 폴더를 만든다(문서에는 없음) |
| `edit` | 편집 | 문서 내용을 고친다(`canEdit` — 실시간 밀어 넣기·수정본·반영·거절 …) |
| `delete` | 삭제 | 문서를 지운다 |
| `manage` | 관리 | 문서·폴더 권한을 바꾸고, 옮기고, 이름을 바꾸고, 빈 폴더를 지운다. 문서 설정(⚙)도 바꾼다(`canConfigure`) |

무엇이든 있으면 `read` 도 있다. 접근 목록(acl)의 이름 `'*'` = 모든 사용자(공용 문서함에서만).

**계산**(`Library.permsAt`·`docPerms`):

1. 관리자(role `admin`) — 언제나 전부(개인 문서함도).
2. 개인 문서함 주인 — 자기 문서함의 모든 폴더·문서에 전부.
3. 자리의 실제 접근 목록 = 폴더가 '상위 따름'(`inherit: true`)이면 위로 올라가 처음 만나는 '직접 지정' 폴더의 acl, 맨 위까지 가면 공용은 `publicRoot.acl`, 개인은 빈 목록(주인만). 그 사람 이름 줄 + `'*'` 줄을 합친다.
4. 폴더를 만든 사람 — 그 폴더에 보기·작성·관리(하위 폴더로 물려주지 않음).
5. 문서: `meta.access` 가 있으면 폴더 권한 **대신** 그 acl. 폴더 관리 권한이 있으면 그 안 문서 보기·관리. 문서를 올린 사람은 보기·편집·관리(삭제는 폴더 권한대로).
6. 역할 `viewer` — 남의 문서함에서는 보기만(위 결과를 `read` 로 자른다). 자기 개인 문서함은 주인이라 전부.
7. 문서 설정의 `editors`(수정 권한 '지정한 사람')는 그대로 남아, 편집 권한이 있는 사람 가운데서 한 번 더 고른다.

**공용 맨 위 기본값** `[{ name: '*', perms: ['read', 'write', 'edit'] }]` — 종전 역할 동작과 같다(편집자 올리기·고치기, viewer 읽기 전용, 삭제는 관리자).

## 3. 접근 문(보이지 않으면 없는 것)

- REST: `app.use('/api/docs/:id', …)` 가 모든 문서 경로(collab·agents 라우터 포함)보다 먼저 `service.assertDocRead` — 볼 수 없는 문서는 404 `NO_DOC`(남의 개인 문서가 있는지도 알리지 않는다).
- WebSocket `/ws?doc=` — 볼 수 없으면 연결을 끊는다.
- MCP — `doc_id` 를 받는 모든 도구가 같은 문(`오류(NO_DOC)`), `list_documents` 는 볼 수 있는 것만. `list_requests`·`claim_next_request`(문서 지정 없음)도 볼 수 있는 문서에서만.
- 드라이브 첨부(`/api/drive/files/:file/attach`)도 같은 문.
- `GET /api/docs` 는 볼 수 있는 문서만. 문서 요약에 `space`·`spaceOwner`·`folderId`·`perms`·`access`(`{ custom }`, 관리 권한이 있으면 `acl` 도)가 붙는다.

## 4. 경로

| 경로 | 권한 | 내용 |
|---|---|---|
| `GET /api/library` | 로그인 | `{ me, publicRoot: { perms, acl? }, folders, docs }` — 폴더는 보기 권한이 있는 것 + (공용) 그 위 폴더(`nav: true`, 길만), 관리 권한이 있으면 `acl`·`effective` |
| `POST /api/folders` `{ name, parentId?, space? }` | 위 자리 작성 | 같은 자리 같은 이름 409 `NAME_TAKEN`, 8단계까지 |
| `PATCH /api/folders/:fid` `{ name?, parentId? }` | 그 폴더 관리 (+ 새 위 자리 작성) | 같은 문서함 안에서만 옮김 |
| `PUT /api/folders/:fid/access` `{ inherit?, acl? }` | 그 폴더 관리 | acl 만 주면 직접 지정. 개인 문서함은 `'*'` 400, 주인 이름은 뺀다 |
| `DELETE /api/folders/:fid` | 그 폴더 관리 | 비어 있어야(하위 폴더·문서 — 볼 수 없는 문서도 센다) 409 `NOT_EMPTY` |
| `PUT /api/library/public/access` `{ acl }` | 공용 맨 위 관리(관리자) | |
| `POST /api/docs` 머리글 `x-space`·`x-space-owner`·`x-folder-id` | 그 자리 작성 | 자리를 안 주면 공용 맨 위, 거기 작성 권한이 없으면 내 개인 문서함 맨 위 |
| `PATCH /api/docs/:id/location` `{ space?, owner?, folderId? }` | 문서 관리 + 새 자리 작성 | 활동 기록 `move` |
| `PUT /api/docs/:id/access` `{ inherit: true }` \| `{ acl }` | 문서 관리 | 활동 기록 `access`, WS `{ type: 'doc', action: 'access' }` |
| `DELETE /api/docs/:id` | 문서 삭제 | 종전: 관리자만 |

## 5. 화면(문서 목록)

- 왼쪽 **문서함 나무**: 공용 문서함 · 개인 문서함 · 드라이브 · (있으면) 공유받은 문서함(주인별 — 관리자에게는 '다른 사람 문서함', 모두 보임). 드라이브를 선택해도 메뉴를 유지하고 문서함을 누르면 해당 위치로 돌아간다. 펴고 접은 것은 브라우저에 기억(`hwpx.lib.open`). 마지막 문서함/드라이브 화면은 탭별·사용자별 `sessionStorage`에 기억(`hwpx.lib.section:<이름>`).
- 오른쪽: 위치 줄(문서함 › 폴더 › …) · 문서 찾기 칸(보이는 문서 전부에서 제목·파일 이름) · [새 폴더] [＋ HWPX 올리기] [권한](지금 폴더를 관리할 수 있을 때, 공용 맨 위는 관리자) · 폴더 줄과 문서 줄. 지금 자리는 브라우저에 기억(`hwpx.lib.loc`), 없어진 자리면 공용 맨 위.
- 문서 줄은 한 번 클릭해 선택하고 더블클릭·Enter·문서 열기 버튼으로 편집기에 진입한다. 편집기에서는 드라이브 메뉴를 숨기며, 기존 패널은 `web/drive-editor.js`에 보관한다.
- 나무와 오른쪽 사이 경계선을 끌어 나무 폭을 바꾼다(180~520px, 화살표 키·두 번 누르면 기본 240px, 브라우저에 기억 `hwpx.lib.sideW` — `web/side-splitter.js`, 2026-11-18). 드라이브 화면의 폴더 칸도 같은 경계선(`hwpx.drive.sideW`).
- 휴대전화 폭(760px 이하)은 나무가 위로 가고 문서 줄이 카드 꼴이다: 이름(줄 전체·줄바꿈) → 파일 이름·올린 사람 → 버전 · 수정 시각 | 단추. 표 머리 대신 정렬 고르기 상자.
- 줄마다 권한이 있을 때만 작은 단추: 폴더 = 이름 바꾸기·옮기기·권한·지우기, 문서 = 열기·옮기기·권한·삭제. 문서만 따로 정한 권한은 '따로' 꼬리표(마우스 올림에 목록), 찾기 결과의 내 개인 문서는 자물쇠.
- **권한 창**: 상위 폴더 따름 / 직접 지정(문서는 폴더 권한 따름 / 직접 지정), 사람 × 보기·작성·편집·삭제·관리(문서는 작성 없음, 개인 문서함은 관리 없음 — 주인 줄은 '전부'). 처음 직접 지정으로 바꾸면 지금 물려받는 목록을 채워 둔다. 역할 viewer 인 사람에게는 '보기 전용' 꼬리표.
- **옮기기 창**: 작성 권한이 있는 자리만 나무 꼴로(폴더는 같은 문서함에서 자기와 그 아래 빼고).
- 보이는 글은 `docs/UI_TERMS.md` 대로 이름표만, 설명은 title·`?`(사용 설명서 `#library`).

## 6. 남은 것·결정

- 외부 드라이브의 HWPX는 **편집함으로 가져오기**에서 공용/개인·폴더를 지정한다. 더블클릭하면 **가져와서 열기**로 바로 편집기에 이어진다. 목적지 작성 권한과 폴더 공유 규칙을 그대로 적용하며 import API의 목적지 생략은 내 개인 문서함이다. **편집함 문서 올리기**에서는 읽을 수 있는 문서만 전송할 수 있다. 검증은 `tests/drive_brave.test.mjs`.

- 관리자는 개인 문서함도 볼 수 있다(요청: "서버 관리자 이외에 지정한 사람만") — 관리자에게도 숨기려면 설정 하나를 더해야 한다.
- 사용자 이름을 바꾸거나 지우면 접근 목록의 그 이름 줄은 남는다(같은 이름을 새로 만들면 그 권한을 받는다).
- 끌어다 놓아 옮기기, 폴더 통째 지우기(안의 문서까지)는 없다 — 비운 뒤 지운다.
- 문서 설정(⚙)의 수정 권한(editors)과 문서함 편집 권한이 겹친다. 하나로 합칠지는 사용자 확인 뒤.
